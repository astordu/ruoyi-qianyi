# 实施迁移

只按已确认的 PRD 实施，从中读取源目录和 React 目标目录；路径缺失时先补清楚。默认不改原 Vue 前端和后端；额外改变需要有当前需求依据。

1. 阅读指定 PRD、相关 Vue 源码、[Vue → React 技术约定](../../../migration/vue-react-convert.md) 及已有 progress.md，确认当前任务。源代码/需求发生影响行为的变化时先说明并更新需求，不用旧结论直接施工。
2. 实现前依 PRD 在原版记录行为、请求及需要对比的截图，保存到当前项目的 `.qoder/migration/<module-id>/`。固定数据、角色和 viewport，保证验证能重放。无法运行原版时明确哪些证据未获得；可继续不依赖它的工作，但最终验证不能当已通过。
3. 按 PRD 的短任务清单实施。小任务一次做完；较大模块一次做一个可验证任务，写下剩余事项供新会话接续，不把任务拆成纯文件编辑碎片。
4. React 工程或公共能力尚不存在时，先建立当前模块需要的最小基础；记录工具选择和实际命令，沿用已有架构。视觉或业务语义的显著变化需要用户决定，不逐项追问普通实现细节。
5. 沿技术约定转换状态、生命周期、表单、路由、权限和 API，优先复用已存在的公共适配层。按任务补有意义的行为测试；合适时先写失败测试再实现，不依赖外部 `/tdd` skill。
6. 运行实际存在的构建、类型检查和相关测试，记录工作目录、命令、结果/日志与未执行项。不得通过删断言、缩减 PRD 或替换原版截图消除失败。

进度只写一个 `.qoder/migration/<module-id>/progress.md`：对应 PRD 版本/更新时间、已完成和剩余任务、React 文件、C 编号映射、公共改动影响、真实自检结果、阻塞、下一步。新会话读它再接着做；遇到同一失败连续修复 3 次无进展，保留证据等待人处理，不无限重试。

实现完成是“待验证”，不能自己写“人工验收通过”。
