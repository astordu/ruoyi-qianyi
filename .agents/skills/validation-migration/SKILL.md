# 验证迁移成果

使用新会话/agent 做正式验证，避免只复述实施者自检。读当前项目的 `.qoder/prd/<module-id>.md`，按其中的源/目标目录核对旧版源码证据、基线和 React 实现；progress.md 只作导航。需要时读 [Vue → React 技术约定](../../../migration/vue-react-convert.md)。不具备独立环境时明确是自检，保留独立验证待办，不伪造独立性。

1. **覆盖核对**：逐 C 编号映射旧版行为、React 文件/函数、运行检查，发现遗漏分支也列出。检查的是行为覆盖，不是每个 Vue 文件是否都有同名 React 文件。
2. **行为验证**：依 PRD 重放成功、异常、校验、取消、空数据、分页、权限、刷新及副作用。核对请求参数、响应/错误和必要真实后端集成；mock 通过只证明 mock 契约，构建通过只证明构建。
3. **相关回归**：共享请求、菜单、权限或布局有变化时，检查影响到的公共行为和已迁移模块。测试选择与风险相称，不能拿后端单测充当前端等价性证明。
4. **截图对比**：用相同数据/权限/viewport/状态捕获真实 React 图，与实施前旧版图比较并实际查看。逐状态记录差异及影响，必要时生成并排/差异图。缺截图工具或原版截图时标为未验证；不换旧基线来消除差异。截图相似不能替代行为检查。
5. **人工验收**：汇总可访问的页面、按场景操作步骤、预期结果、原/新截图和检查证据，供人确认。真实用户反馈才可记为人工接受；agent 自检或用户沉默不算。

只输出 `.qoder/migration/<module-id>/validation.md`，包含：

- 本次 PRD、源码和目标的检查日期/版本；有 Git 时记 revision，无 Git 时记关键变更及检查范围。
- 每条条件的矩阵：C 编号、源码/实现证据、实际检查与日志、通过/失败/未验证。
- 原图/目标图的本地路径和逐状态观察；未解决差异及已获真实反馈。
- 缺陷复现、预期/实际、归属任务；最终人工操作清单和真实验收反馈。

总体结果区分“通过机器验证、待人工确认”“失败”“未验证”“人工已确认”。所需条件/截图/集成证据缺失不能给总体通过。问题交回 implements-migration 修复，修复后重新检查受影响项；需求或相关代码后来变化时，旧报告只代表旧版，不能直接沿用。
