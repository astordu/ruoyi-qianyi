# 运行迁移循环

在项目根目录运行：

```sh
./migration-loop.sh claude 500
```

沿用已登录的 Claude CLI 和默认模型。也支持 `codex`、`qodercli`；指定模型使用 `--model`。脚本默认不提交、推送或部署。

先预览、不修改状态或调用模型：

```sh
./migration-loop.sh claude 500 --dry-run
```

循环读取 `migration/state/` 的现有计划，每次选一个完整能力组，在独立 CLI 会话分别执行选组、实施、验证。组内可以跨会话继续，验证失败直接修复当前组，不生成函数/文件子计划。所有组通过后逐项验证集成并生成最终报告。

实施改动使共享依赖的验证失效时，先保存当前组的 `implemented` 进度，由调度器暂存本轮、复验依赖，再恢复当前组验证。超时计数始终绑定实际调用的组/集成编号，不因为下一候选变化而串组。真实业务或环境阻塞仍保留 blocked，不能自动跳过条件标通过。

`500` 是外层执行轮数上限，完成会提前退出。55 组加 10 项集成需要至少 65 个执行轮；每轮可能调用多次 CLI，收尾报告另开一次会话。这与计划所说的约 56 个逻辑轮（55 组加一个整体验收阶段）计数方式不同。实际修复、复验或中断可能增加次数。

每次 CLI 默认最多运行 2400 秒（40 分钟），超时保留代码和状态，自动在同一阶段额外续跑最多 3 次。已合法保存的阶段结果直接推进。验证失败最多自动修复 3 次；两类计数跨脚本重启保留，分别用 `--max-timeout-retries`、`--max-retries` 调整。Ctrl-C 或 SIGTERM 会终止当前 CLI 进程组并保存已有进度；重新运行同一命令续做。

日志在 `migration/state/loop/runs/<运行编号>/`，超时计数与上次日志路径在 `migration/state/loop/timeout-counts.json`。运行日志和锁不进入 Git，实际迁移代码、状态及验证证据仍需正常提交。

退出码：`0` 完成，`1` CLI 失败，`2` 状态/配置问题，`3` 阻塞或修复次数耗尽，`4` 达到执行轮数上限，`124` 超时续跑耗尽，`130` 用户中断。CLI 成功退出不代表行为验证通过，必须有有效的落盘报告和记账证据。
