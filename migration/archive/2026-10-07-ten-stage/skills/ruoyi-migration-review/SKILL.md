# 独立覆盖与行为验证

读 [共享协议](../../../migration/CONTRACT.md)、原 spec/scenarios/approval、source/target 清单和 baseline，再读原版证据与 React 实现。implementation.md 仅为线索，不是正确性依据。

必须在不同于实施者的干净会话/agent 执行正式评审。已有用户授权且工具支持时可安排独立 agent；没有工具/授权则写评审交接包供新会话执行，不假称独立。当前实施会话可以自检，但正式状态保持 unverified。

1. 先校验清单与真实文件、需求哈希、baseline 绑定。变化使旧报告失效，返回对应阶段。另查新出现的依赖/分支是否漏入原证据。
2. 逐条 required C 建矩阵：原版依据、React 函数/组件、API/状态对应、测试或运行观察、pass/fail/unverified。文件数相等、函数名存在、构建通过均不能替代行为覆盖。
3. 真正重放成功与异常、取消/校验、空数据/分页、无权限/直接访问、刷新和写入副作用。按条件选择函数测试、浏览器操作、请求契约与真实后端集成；只有 mock 时注明仍缺哪些集成证据。
4. 核对本次共享代码影响的登录、菜单、权限、字典、请求/下载和其他已迁移模块。按依赖做针对性回归，不把后端单测当 React UI 等价性证据。
5. 写 review.json 和可定位的缺陷：C、复现条件、预期/实际、原/新源码、运行日志、优先级、归属任务。检查验收测试是否被削弱、原版截图是否被换掉。

总体 pass 要求每条 required 条件都有适当的真实通过证据、相关集成/回归完成、版本绑定有效。缺环境标 unverified/blocked；可修复失败回 implementing 并累计次数。评审不擅自修复，以便保留实施与核验边界。

保存 state/handoff；行为通过后继续 visual，二者都完成才能进入人工验收。
