# 形成可审阅的验收成果

读 [共享协议](../../../migration/CONTRACT.md)、已确认需求、任务、基线、review/visual、source/target 清单。检查实际文件与报告绑定，不只读状态摘要。

1. 核对所需公共依赖已完成、所有 required 条件有通过证据、相关集成/回归完成、要求截图齐全、差异已解决或已由人接受、无未解决阻塞。未满足则列出具体缺口并回对应阶段，不让人替 AI 补未做的检查。
2. 写 acceptance.md：启动/访问方式、账号配置引用、测试数据与复位方法、按场景的人工操作步骤、预期结果、原/新截图和运行证据链接、已同意差异、绑定版本。
3. 给用户一份短而具体的待验收成果；用户实际确认前 state 保持 ready_for_acceptance/awaiting_human。不能因为 tests pass、没有回复或另一个 agent 认可而写 accepted。
4. 收到反馈后原意记录时间和对象，问题转对应任务并使旧相关报告失效；真正确认后记录需求、源、目标和报告哈希，状态 accepted。

人工可明确调整需求，但必须记录变更并补对应验证，不能静默豁免失败项。React 或源版本后来变化时，旧验收只代表旧版本，不自动确认新的版本。最终交接指出下一个由人选择/已确认的模块；不自行扩大迁移范围。
