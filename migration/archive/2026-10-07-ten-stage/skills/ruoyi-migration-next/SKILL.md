# 推进一次并交接

先读 [共享协议](../../../migration/CONTRACT.md)、project.json、该模块 handoff/state，再核对阶段所需原始文件、真实人工反馈和指纹。state 是索引，不能凌驾于证据。

需求哈希与 approval 不符，返回 research 并确认变更；源文件变化先核实需求/原版基线影响；目标变化先使相关 review/visual/acceptance 失效。不得从旧 state=accepted 直接跳过这些检查。

按最早缺失的门槛选择一个动作，并读取同目录下对应 skill 的 SKILL.md：

| 状态 | 下一步 |
| --- | --- |
| 未选范围 / scope 不清 | scope，逐个澄清关键问题 |
| 场景及证据未成形 | research |
| 需求待人确认 | awaiting_human，保存具体待确认材料，暂停该模块 |
| 公共能力缺失 | foundation 的一个依赖任务 |
| 原版行为/截图基线缺失或过期 | baseline |
| 任务未规划或与需求不一致 | plan |
| 存在依赖满足的待实施任务 / 有可修复缺陷 | implement 一项 |
| 实施完成且行为证据缺失/过期 | 独立 review |
| 视觉证据缺失/过期 | visual |
| 全部机器门槛满足 | accept，等待实际最终反馈 |
| 当前版本已接受 | 返回 accepted，不重复改代码 |

每次最多执行一个阶段步骤或一个实施/公共基础任务，然后更新 tasks/state/handoff；不在一个长会话里无限自调用。新代码变化导致旧报告失效时，把受影响检查重新安排。

handoff 必须包含模块/任务 ID、需求版本、必读源码/资料、下一 skill、真实已做检查、阻塞及累计修复次数。禁止把“计划运行”写成“已通过”。

缺服务/账号/决策、依赖阻塞、达到修复上限时，返回具体 blocked/awaiting_human，不重启掩盖问题。默认任务与阶段最多修复 3 次；保留计数。若用户已明确多个模块及优先级，可报告其他不受阻塞模块的下一步，不自行选择新业务范围。

真正启动新上下文由外层调度器或用户新会话完成。可用且已授权的工具才能启动 agent；没有则只交接，不假称自动运行。正式 review 必须换实际会话/agent；当前实施者不能在 next 中换个标题就算独立评审。
