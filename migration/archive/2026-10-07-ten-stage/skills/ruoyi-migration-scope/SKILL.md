# 收集迁移范围

先读 [共享协议](../../../migration/CONTRACT.md) 和 [项目事实](../../../migration/PROJECT.md)。沿用用户已指定的 React 目录 `react-front/`。

参考 grill-me 的访谈方式：一次只问一个影响边界的关键问题，给出推荐答案和影响；等待回答后再问下一个。可由源码、路由、菜单或环境得到的事实自己查，人的决策不能代答。普通实现细节由 agent 判断，不做无止境访谈。

1. 从用户指定模块开始，搜索实际页面/路由/菜单，给用户一份简短的功能清单。区分代码中存在、当前菜单可见、环境尚未核实。
2. 查明模块包含的隐藏详情页、弹窗、授权操作、导入导出、关联跳转；只追踪范围所需依赖。先问最影响范围的未知选择，不一次抛整张问卷。
3. 记录纳入和排除、必须保留的行为/视觉、允许改善、依赖模块、账号/数据条件。没有账号时照样完成代码范围草稿，标明运行未知。
4. 写 `migration/modules/<module-id>/scope.md`，保存实际用户决定与未决项。可以先保存草稿；在用户未确认前不擅自实施迁移。
5. 输出可供用户确认的具体边界，写 state 和 handoff，下一步指向 research。范围确认不是宣称场景已完整；还要用代码证据还原场景后确认完整需求。

用户一句话已明确模块时，不为开始调研重复要许可。访谈期间可以继续独立查代码，但不得把未回答项当已确认。
