# 按可验证行为拆任务

读 [共享协议](../../../migration/CONTRACT.md)、模块 scope/spec/scenarios/approval、源指纹、baseline 及公共基础任务。确认资料是否过期；可先写草稿计划，但输入未就绪的任务必须 blocked。

1. 先列共享依赖、模块入口、读操作、写操作、异常/权限、测试与集成关系。模块小时可只设一个实施任务；避免按每个文件拆出碎片任务。
2. 写 tasks.json。每个任务有 S/C 映射、前置依赖、允许修改路径、实施边界和真实检查命令/步骤。单个任务完成后必须能检验一个有意义结果。
3. 建条件→实现任务→验证证据映射：所有 required 条件有归属，无重复矛盾，依赖无环且引用真实任务。权限、请求/副作用、错误处理、隐藏页不能漏给实施任务。
4. 缺公共能力先设 foundation 依赖；跨模块跳转/共享修改标出受影响模块的回归检查。只允许 react-front/ 与迁移资料中的具体路径；更宽修改必须有已确认理由。
5. 检查测试命令确实存在，不填写 npm test 等臆造命令；未建的测试作为任务，而不是已通过门槛。review/visual/人工验收是单独阶段，不由实施任务自行完成。

保存可运行任务与 blocked 原因，repair_attempts 从 0 开始且跨会话保留。state 指向第一个依赖满足的任务，handoff 给该任务所需需求、源码、基线、文件边界和验证方式。
