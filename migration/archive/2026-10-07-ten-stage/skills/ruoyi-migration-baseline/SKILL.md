# 固定原版验证基线

读 [共享协议](../../../migration/CONTRACT.md)、已确认 spec/scenarios/approval 和 source-manifest。检查确认及源指纹有效，基线在模块实现前建立。

1. 检查已有测试真正覆盖哪些验收条件；当前 CI 引用的缺失目录不能算现成 E2E。只补当前范围缺失的有意义检查，不以单元测试数量替代行为验证。
2. 记录原版/后端启动命令、端口、浏览器、viewport、账号角色、语言/时区、数据准备与复位。使用本地测试数据；账号口令不写入文档或日志。写 environment.md，后续 React 复用同一条件。
3. 在旧 Vue 系统重放每个场景，记录可观察结果、必要 API 请求/响应字段和副作用。缺服务/账号/权限时完成静态工作并列出具体 blocked，不虚构成功操作。
4. 在测试适合的位置建立与框架无关的行为步骤或测试；选择测试选择器和断言，不能依靠 Vue 内部函数名验证 React。复杂纯函数可单测，UI 操作需浏览器证据。
5. 捕获场景需要的旧版截图，至少覆盖需求中列出的列表/弹窗/错误/权限状态。截图必须来自真实运行和检查；记录稳定化及遮罩规则。
6. 写 baseline.json，逐条件记录 pass/fail/unverified、运行证据、截图、已知旧缺陷及版本绑定。失败的旧行为是否迁移/修复按已确认需求决定。

把基线、测试及固定数据当受保护的验收输入。发现需求缺口返回 research，而非自行改预期。保存 state/handoff；基线未覆盖必需条件时不得把实现任务标成可验证完成。
