# Vue → React 转换约定

这是 Vue → React 的通用实现参考。源/目标目录、迁移边界和项目具体约定以本次 PRD 为准。先识别 Vue 版本、状态管理、组件库及运行方式；涉及 SSR 时把服务端行为纳入 PRD，不默认按 SPA 处理。只读当前模块需要的部分。

## 转换原则

迁移用户能观察到的行为和后端契约，不逐行翻译 Vue，也不强求文件一一对应。尽量复用不依赖 Vue 的纯 JS 工具，隔离 UI 提示、状态与路由依赖。公共能力只建立一份；React 工程不存在时先补当前模块需要的最小基础。

React 的 JS/TS、路由、状态和 UI 库尚未由本流程预选。实施时检查已有工程/决定，记录选择。若库替换显著改变旧界面，先展示具体差异供人决定；不得把功能迁移自行扩大为产品重设计。

## 状态、模板和生命周期

| Vue 用法 | React 转换关注点 |
| --- | --- |
| data / ref / reactive | 区分需要触发渲染的 state 和仅存可变引用的 ref；更新对象/数组用新值，避免直接修改状态 |
| computed | 优先从当前 props/state 派生值；昂贵计算才按实际需要缓存，避免存重复状态造成不同步 |
| watch / watchEffect | 区分用户事件、派生值和外部同步；不要把所有 watch 机械改成 effect。检查依赖、清理及旧值语义 |
| 生命周期钩子 | 按源版本核对挂载/销毁逻辑，外部订阅、计时器、图表和编辑器有创建/清理；处理卸载后的请求及重复初始化 |
| v-model / 自定义组件事件 | 核实源版本的值与事件契约，转成明确的受控值和回调；保持数字/字符串/空值语义和重置行为 |
| v-if / v-show | 区分卸载与隐藏；表单重置、实例状态、校验残留行为要与需求一致 |
| v-for / key | 用稳定业务 key；排序/分页/编辑列表时检查选择和输入状态不串行 |
| slots / scoped slots | 显式 children、render props 或组件 props；保留回调参数及表格单元格行为 |
| provide/inject / Vuex / Pinia | 只把确需共享的数据放公共层；核实相关身份切换或业务上下文变化时的清理和刷新 |
| nextTick / DOM refs | 先确认是布局、焦点还是外部控件需求；不要简单用 setTimeout 替代 |
| KeepAlive | 记录切页时是否保留查询、滚动、表单和请求；按已有路由/UI 能力实现，不能无意丢掉缓存语义 |

请求更新尤其注意快速筛选/切换记录时的乱序响应、重复发送及关闭页面后的处理。React 开发模式可能暴露副作用重复执行问题，应检查资源清理和写操作触发位置；不要靠关闭开发检查隐藏缺陷。

## 表单和 UI 控件

识别源项目实际使用的组件库，核对目标组件的值、事件和默认行为。逐场景核对表单初始值、校验时机/文案、必填/自定义规则、取消与保存、打开不同记录后的重置。PRD 指定的失败行为也必须实现。

表格要保留 row key、选择项、分页起点、排序/筛选、空态/加载态和保存后刷新规则。树选择、日期、字典标签、上传/下载需核实值类型、时区、文件协议及权限。不要把 ID 数字和字符串混用、把日期本地显示值直接当后端时间格式。

图表/富文本/代码编辑器/拖拽等依赖要查 Vue 封装之外的实际库及数据格式，React wrapper 不存在时可通过 DOM ref 管理底层实例并清理；不为了页面能渲染就换成无功能占位。

样式检查 Vue scoped CSS、深层选择器、主题、图标和 UI 库 class 名的差异；移植时限制选择器作用域。视觉以 PRD 指定状态下的真实截图比较。

## 路由、权限和请求

从实际源码定位路由与请求入口，保留 params/query、重定向、页面缓存和部署路径行为。若存在动态菜单或权限守卫，保留加载时机与访问限制；后端返回组件标识时，建立 React 映射并明确未迁页面的处理方式。

核对项目实际使用的认证、参数编码、业务错误、取消/重试、上传下载和副作用约定，写入 PRD。加密、防重复提交等机制按源项目实际情况保留，不预设其存在。隐藏按钮、路由限制与后端授权分别验证。

复用纯 JS API/工具前检查依赖，避免把 Vue 状态层或 Vue UI 库间接带进 React。接口与后端行为默认保持兼容。

## 验证边界

从实际项目配置核实启动、构建和测试命令，检查测试覆盖的行为；只运行实际存在的命令，并补当前模块所需检查。

纯函数/转换规则可单测，页面行为用浏览器步骤/E2E，API 用请求断言及必要真实后端集成；用 mock 时明确证明范围。验证者按 PRD 每条条件选适当证据，不强制每项都套单元测试。构建成功、类型检查和截图相似均不能证明完整业务等价。

原版截图在实施前采集，记录相同账号、数据、viewport、时区/语言及弹窗/加载/错误状态；目标复用同条件。动态时间等噪声需两边一致处理并说明。缺运行环境留未验证，禁止伪造截图或覆盖旧图。

共享菜单、请求、权限或布局变动需要检查实际受影响模块。新代码或 PRD 改变了行为，重新验证相关条件；独立 validation 最后提供人能操作的验收步骤。
